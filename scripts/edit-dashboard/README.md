# Local edit desk

Open **http://127.0.0.1:8976/** on M6. This shows registered edits, observed render slots, edit/render waiters, recorded owner reviews, route reservations and the shared line. Expand Machine details for the render allowance, outside work and feature state. No control endpoint is provided.

**Install or repeat installation on M6:** from the live project, run `python3 scripts/edit-dashboard/install.py`. This uses the existing `m2` SSH identity and the installed Apple developer tools. The installer preflights the loopback port and only replaces its own files. Runtime lives at `~/.local/share/abs-edit-dashboard/` on each machine. M2 has a short-lived helper only. M6 has `~/Library/LaunchAgents/com.absbyai.edit-desk.plist`. A visit wakes the worker, which exits after 75 seconds with no requests. The socket remains available through the current login and future logins. There is no website/cloud deployment.

**Restart only this dashboard:** on M6, `launchctl kickstart -k gui/$(id -u)/com.absbyai.edit-desk`. Loading the page normally needs no command. Error log: `~/.local/share/abs-edit-dashboard/service.log`. Checking that socket activation is registered without waking it: `launchctl print gui/$(id -u)/com.absbyai.edit-desk`.

**Remove:** on M6, `launchctl bootout gui/$(id -u)/com.absbyai.edit-desk`, then remove the named plist and the dashboard runtime directory above. Remove **only** `~/.local/share/abs-edit-dashboard/` on M2. There is no remote service to stop. Leave the separate review hub, editcap, renderq, route, archive, dispatcher and all production folders alone.

**Data and limits.** A visible page asks for an update once a minute. Tabs share each host's collection; the normal minimum interval is 58 seconds with a 12-second minimum for deliberate Refresh. GET /state only reads the shared cache. M6 returns independently of M2. An SSH failure immediately prevents start advice even while the last good reading is displayed. Readings over two minutes old are stale. The observer never takes scheduler locks, mutates queues, enumerates footage or probes external storage. It asks Darwin about existing read-only descriptors and matches inode, PID and process birth before reporting a held step. Unrecognized work names stay private and cannot establish a free slot. The router alone checks the specific job, ownership, drive space, priority and render admission. A slot count is not CPU utilization. Unknown/old input is conservative; only the recorded edit register may identify a possible stall.

**Source compatibility.** The adapter recognizes the reviewed policy files by digest (including the help-argument repair on Nov 14), reads actual host settings and feature state, and masks blind comparison identifiers before serializing a snapshot. A new policy digest needs source review, then an update to this dashboard's policy.json. Do not change a scheduler file to satisfy the dashboard. Do not configure a network drive as an observation state directory.

**Tests:** on this Mac, `python3 -B scripts/edit-dashboard/test_dashboard.py`. The test compiles its private kernel helper and creates temporary state files; no real slots are registered, promoted or released. Installation and measurements: see Docs/two-mac-dashboard/receipt.md.
