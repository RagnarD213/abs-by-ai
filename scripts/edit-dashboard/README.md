# Local edit desk

Open **http://127.0.0.1:8976/** on M6. This shows registered edits, observed render slots, edit/render waiters, recorded owner reviews, route reservations and the shared line. Expand Machine details for the render allowance, outside work and feature state. No control endpoint is provided.

**Install or repeat installation on M6:** from the live project, run `python3 scripts/edit-dashboard/install.py`. This uses the existing `m2` SSH identity and the installed Apple developer tools. The installer preflights the loopback port and only replaces its own files. Runtime lives at `~/.local/share/abs-edit-dashboard/` on each machine. M2 has a short-lived helper only. M6 has `~/Library/LaunchAgents/com.absbyai.edit-desk.plist`. A visit wakes the worker, which exits after 75 seconds with no requests. The socket remains available through the current login and future logins. There is no website/cloud deployment.

**Restart only this dashboard:** on M6, `launchctl kickstart -k gui/$(id -u)/com.absbyai.edit-desk`. Loading the page normally needs no command. Error log: `~/.local/share/abs-edit-dashboard/service.log`. Checking that socket activation is registered without waking it: `launchctl print gui/$(id -u)/com.absbyai.edit-desk`.

**Remove:** on M6, `launchctl bootout gui/$(id -u)/com.absbyai.edit-desk`, then remove the named plist and the dashboard runtime directory above. Remove **only** `~/.local/share/abs-edit-dashboard/` on M2. There is no remote service to stop. Leave the separate review hub, editcap, renderq, route, archive, dispatcher and all production folders alone.

**Data and limits.** A visible page asks for an update once a minute. Tabs share each host's collection; the normal minimum interval is 58 seconds with a 12-second minimum for deliberate Refresh. GET /state only reads the shared cache. M6 returns independently of M2. An SSH failure immediately prevents start advice even while the last good reading is displayed. Readings over two minutes old are stale. The observer never takes scheduler locks, mutates queues, enumerates footage or probes external storage. It asks Darwin about existing read-only descriptors and matches inode, PID and process birth before reporting a held step. Unrecognized work names stay private and cannot establish a free slot. The router alone checks the specific job, ownership, drive space, priority and render admission. A slot count is not CPU utilization. Unknown/old input is conservative; a stall comes from the edit register. When the edit queue records a draft or delivered cut for owner review, it releases the registered edit on its production Mac. The desk also reconciles the handoff time on refresh. A later production round takes precedence over an older review.

**Source compatibility.** The adapter recognizes the reviewed policy files by digest (including the help-argument repair on Nov 14), reads actual host settings and feature state, and masks blind comparison identifiers before serializing a snapshot. A new policy digest needs source review, then an update to this dashboard's policy.json. Do not change a scheduler file to satisfy the dashboard. Do not configure a network drive as an observation state directory.

**Tests:** on this Mac, `python3 -B scripts/edit-dashboard/test_dashboard.py`. The test compiles its private kernel helper and creates temporary state files; no real slots are registered, promoted or released. Installation and measurements: see Docs/two-mac-dashboard/receipt.md.

**Edit counts versus helper work (November 16):** Only active/promoted edit registrations count toward whole-edit slots. Render-only or queued setup/QA work stays visible under “Setup / helper work (not edit slots)” with its render load retained. A finalized/uploaded job with render work but no active edit registration is labeled setup; a later active registration still takes precedence. Each job appears in only one primary section. No registry or worker is changed by this display classification.

The desk reads the M2 dispatcher's batch state files and uses the latest round per video. The shared line omits jobs already shown on their assigned Mac. A routed reservation, edit-slot wait and render backlog are distinct. Historical decisions in desk_records.py apply only to the exact reviewed handoff. The owner list uses the current question and review link from the batch outcome or edit handoff. Incomplete handoffs are flagged for investigation. For new manual handoffs use editcap release JOB --review --question "..." --link URL or queue.py set JOB draft_review --question "..." --review-url URL. Anonymous render tickets may carry a display-only work folder; old tickets can be identified from a verified live worker's input path. This never changes render scheduling.

**ETAs (2026-11-18):** each job row shows its finish-time range from `tmp/edit-queue-export/edit-queue-eta.json` (written every 10 minutes by `.claude/skills/_shared/eta/eta.py refresh`, LaunchAgent `com.absbyai.edit-eta`). The server only reads that file; a missing file shows no ETA lines. Method: `.claude/skills/_shared/eta/README.md`.

**Waiting for Dan is complete (2026-11-19):** a review released without `--question/--link` no longer drops into the yellow "needs checking" line. The observer finds the job's newest review page in the review hub (`~/Library/Application Support/AbsByAI Review Hub/pages/*.json`, a folder named after the job) and shows it with a default question. An older review of a video is hidden once a later round with the same title registers (Joint Vigor R4 after R5 started). Editors should still pass `--question` and `--link`.
