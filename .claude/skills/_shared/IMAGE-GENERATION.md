# Image generation goes through Codex (Dan, 2026-10-01)

**Every image a session generates is made by Codex on Dan's ChatGPT subscription, not by a paid API.**
This covers every skill and every ad hoc request: generated images, backgrounds and plates, AI start and
end frames for clips, long-form thumbnails, shorts covers, Instagram posts, marketing images, retouch
passes. Dan tested it against Nano Banana Pro on 2026-10-01 and ruled: "everything is now Codex."

Wherever a skill, script or handoff says Nano Banana Pro, Gemini 3 Pro Image, `gemini-image.js`,
`rep-t2i.js`, `replicate-edit.js`, Seedream or FLUX for a still image, read it as this helper instead.

## How

```bash
.claude/skills/_shared/codex-image.sh --prompt-file p.txt --out result.png [--image ref.jpg]...
```

**Thumbnails and covers always pass `--model gpt-6.1-sol --effort high`** (Dan, 2026-10-02), unless he names another model.

No handoff and no separate Codex task: the session calls it directly, the way it used to call Gemini.
One image takes about a minute and 22,000 to 40,000 Codex tokens. Run several at once with `&` and `wait`.
State the image count before a batch; it draws on the Codex allowance, so do not generate spares.

## What Codex gives back, and what to do about it

- **Size.** About 1672x941 (16:9), 941x1672 (9:16), 1122x1402 (4:5), 1024x1536 (2:3). Upscale locally
  with Real-ESRGAN when the deliverable needs more (shorts covers need 1080x1920). Never a paid upscaler.
- **It redraws people.** Told "do not edit the man", it still changed Dan's skin tone and size. So when
  the piece uses a real photo of Dan, generate the BACKGROUND ONLY with Codex, then layer his real cutout
  (`photos/finalized social media photos/_cutouts/`) and the type on top in code. This is how the Jelly
  Beans cover and the studio posts are built, and it stays the rule.
  **AI Dan choices are explicitly authorized (Dan, 2026-10-25):** each initial five-choice cover/thumbnail set requires two distinct AI-generated or AI-enhanced images of him acting out the topic, one real pool OR studio photograph, and two history-guided Codex choices. The latter may include more AI Dan. Give every AI Dan generation a real identity reference and inspect the actual face. The real-photo slot retains original person pixels; this permission never turns it into an AI redraw. Full mix and learning rule: VIDEO-RULES, "Thumbnails: the five".
- **It adds bulk.** For a generated Dan (no real photo available), say "lean and shredded, not bulky,
  same size as the reference" in the prompt.
- **Text.** It spells headlines correctly but lets them touch the head and arms. Type that ships is set
  in code, not generated.

## Not covered

- The live app. `server.js` generates for visitors through the API and cannot use a subscription.
- AI video generation (Kling, Veo, Wan). Since 2026-10-17 every AI clip in an editing task, Kling jobs included, is generated on the Google
  Veo subscription (Google Flow on Dan's Google AI Pro) first: `_shared/veo/README.md`; the paid API only when Dan says rush, accelerate or as fast as possible (VIDEO-RULES, "AI video clips").
- Background removal, upscaling, cropping and compositing. These are local tools, not generation.

## The old API scripts are locked

`gemini-image.js`, `rep-t2i.js` and `replicate-edit.js` refuse to run for still images unless
`ALLOW_API_IMAGE=1` is set. Set it only when Codex has failed twice on the same image, or Dan asks for
the API by name. Say so in chat when you do, with the cost.

## Blind Google test (Dan, 2026-10-30)

Dan upgraded to Google AI Ultra and wants a running blind comparison of Codex against Google's image model (Nano Banana Pro).
Dan: "two sets of starting frames for all clips going forward, one generated by Google and one by Codex. Don't tell me which
is which... Eventually, I'll ask you, 'Which ones did I choose the most?'" Codex stays the default maker and the only maker of
anything installed without a pick; Google images exist to be compared. Google runs on the subscription in Flow, never the paid
API: `_shared/blind-image/FLOW-IMAGE-RUNBOOK.md`.

- **Never label the source** in chat, on review pages, in file names Dan sees, or in the setup receipt shown to him. Use
  `_shared/blind-image/blind.py` (`add`, `build`, `pick`): it writes neutral same-size copies named X1..Xn with no metadata, keeps
  the key hidden, logs picks to `~/.absbyai-image-picks.jsonl`, and installs the winner from the original, never the normalized copy.
  If a Google image carries a visible mark or other tell, report it to the main agent instead of showing it.
- **Clip start frames:** every AI clip gets two start frames, one Codex and one Google, same prompt and references, shown as a
  blind pair. The end frame is then made with the model whose start frame Dan picked, for identity continuity. Both frames still pass
  the frame gate and reviewer; a Google frame that fails twice is dropped and the Codex frame goes forward unlabeled.
- **Thumbnails and covers:** the five Codex designs stay as the rule requires, plus **three Google options** (extra designs
  following the same mix and pick-history guidance, not copies of the five), all eight shuffled together unlabeled. Dan's pick is
  logged with `blind.py pick`.
- **Everything else** (Instagram posts, ad stills, plates, marketing images): add up to three Google alternatives to the Codex
  set, unlabeled and shuffled, **unless impractical**: a background or plate that is not itself approved, a repeated asset in a video,
  anything where extra choices would force Dan to approve more than the task needs. Impractical means no Google twin, no note to Dan.
- **Refusals count as results.** If Google refuses an image (Dan's shirtless body is the likely case), log it in the set folder and
  the scorecard note; the Codex image goes forward. Never reword around a safety filter.
- **Real-photo choices stay real** and are never part of the test. App-generation for visitors is out of scope.
- **The scorecard is answered only on request.** When Dan asks which he chose most: `blind.py scorecard` (optionally `--kind`),
  then say plainly which source won by kind, with counts and offered-vs-picked rates. Until then, no hints, including "Google did
  well this time".
- **Cost:** subscription credits only; state the Google image count in the same pre-batch line as the Codex count. Ultra credits
  also feed Veo, so keep an eye on the balance (Fast clips cost 10 credits each).
