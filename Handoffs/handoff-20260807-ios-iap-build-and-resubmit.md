## Key Decisions Already Made

- **Build real IAP** (Dan, 2026-08-07) — hiding purchase UI failed rejection 1, US link-out failed rejection 2, Apple demanded IAP twice in writing. Do not relitigate.
- **RevenueCat over raw StoreKit 2** — receipt validation, renewals, restores, grace periods and webhooks for free; Apple remains the source of truth and RevenueCat never touches money.
- **Product IDs `…membership.annual` / `…membership.monthly`** — permanent, already created. `.annual` (not `.yearly`) so it matches `MEMBERSHIP_PLANS.annual` in `server.js`.
- **Annual listed first / ranked above monthly** — better value and better retention, and it makes monthly→annual an upgrade rather than a downgrade in Apple's billing.
- **Both plans get the 7-day free trial** ("1 Week" in Apple's UI), matching the web copy. Apple grants it once per subscription *group*.
- **Prices are read from StoreKit at runtime, never hard-coded** — a price on screen that disagrees with what Apple charges is itself a rejection reason.
- **Buying is gated behind having an account** — RevenueCat's `appUserID` is our `users.id`, and it is the only key the webhook has to find the account to unlock. An anonymous purchase could never be matched to anyone.
- **The external website link stays alongside IAP** — permitted on the US storefront, and it preserves the cheaper Stripe path for anyone who prefers it.
- **US-only availability stays** (set 2026-08-05).
- **Apple developer account stays Individual / W-9 as Daniel Rose with SSN** for now. Converting to an Organization (Rose Digital Holdings LLC) requires a D-U-N-S number and Apple verification, and **must happen before the S-corp election takes effect** — after that a 1099-K to his SSN against S-corp-reported revenue is a real mismatch. The bank account is changeable any time; the payee entity is not.

## Things to Avoid / Lessons Learned

- **Do not expect the products to reach "Ready to Submit" on their own.** All metadata is present; the state is gated on the app-version submission. Do not go hunting for missing fields — that was already checked field-by-field through the iris API.
- **Do not archive Debug.** Release only.
- **Do not test with the comp demo account** (`danroseconsulting+applereview@gmail.com`) — comp accounts intentionally render no purchase UI, so it will look broken when it is working correctly.
- **Do not run generations on the demo account** — it displaced the curated beach-man hero once before, and the app is in review.
- **Uploading files into App Store Connect from the browser does not work** and cost real time this session: the page's CSP blocks a `fetch` from a localhost asset server (Private Network Access headers do not help), and `mcp__claude-in-chrome__file_upload`'s `paths` parameter is broken. Hand Dan the file and use `open -R` to reveal it in Finder.
- **App Store Connect's `<select>` elements ignore clicks and synthetic keystrokes.** Set them with the native `HTMLSelectElement.prototype.value` setter plus bubbling `input`/`change` events. The price and country pickers are custom components and must be clicked normally.
- **RevenueCat's Authorization field is `type=password`**, so LastPass hijacks it and makes the whole tab un-scriptable. Fill it via the native setter; reload to clear the hijack.
- **Two sessions in one repo:** `git pull --rebase` publishes whatever else is sitting unpushed on `main`. Check `git log origin/main..HEAD` before every push. This session published another session's ab-ladder revert by accident (it was the correct change, but it went out under the wrong push).
- Server-side, **never** grant a membership on the client's word — `/api/apple/sync` asks RevenueCat with the secret key. Same lesson class as the F1 credit double-spend and the locked-image unlock token.
